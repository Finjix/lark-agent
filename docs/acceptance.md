# 验收与回归

自动测试：`project.cmd test`。覆盖分帧、乱序与坏增量、精确轮次路由、内部推理过滤、数字交互 ID、SQLite 去重与恢复、终态与 outbox 原子性、并发锁、跨用户权限、未知提交、越界文件、UTF-8 卡片长度及投递重试。

Desktop 实机测试：

```bat
runtime\node\node.exe scripts\verify-desktop.mjs --live
runtime\node\node.exe scripts\verify-desktop.mjs --live --parallel
```

测试会使用账号额度并创建机器人拥有的临时聊天。并发模式创建五个任务（用户 A 三个、B/C 各一个），验证最多四个执行、每人最多两个、超额排队、独立目录和精确最终结果；结束后归档已完成的测试聊天。报告保存在 `data/verify-*.json`，不会进入交付包。

发布前还需实机验收：

- 使用已配置的飞书测试用户，验证私聊及群聊事件、卡片持续更新和最终附件。
- 普通终端移除继承的 Codex 上下文变量后启动，验证无需当前聊天即可创建任务。
- 服务在执行中停止并重启，核对相同 thread/turn，确认没有重复执行。
- Desktop 重启后重新发现工具端点、恢复订阅并处理原任务。
- 验证真实授权、补充信息、拒绝和中断请求，以及失联时不误报终态。
- 解压离线包到包含中文和空格的新目录，屏蔽系统 Node/npm 路径后运行诊断和自动测试。

单元测试通过不代表以上全部实机验收已完成。当前验证结果由执行记录另行报告。
